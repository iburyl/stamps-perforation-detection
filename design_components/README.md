# Разделение компонентов печати

Этот каталог содержит исследовательские прототипы для разделения печатных
слоёв по цвету и остаточным микросдвигам. Они используют геометрическую
регистрацию из `data_*_perf.json` и `data_*_design.json`, но не подключены к
production pipeline и не меняют его результаты.

Текущий рекомендуемый прототип для `XIX/1R` —
`background_pattern_refinement.py`. Остальные файлы сохранены как базовые и
отрицательные эксперименты, чтобы не повторять уже проверенные подходы.

## Текущая модель XIX/1R

В скане наблюдаются не три цвета, а три печатные краски плюс бумага:

| Компонента | Эффективный scanner RGB | Роль |
| --- | --- | --- |
| тёмная краска | `#4E3B3D` | рамка, надписи и основной орнамент |
| красная краска | `#C05B51` | центральный овал, герб и цифра номинала |
| светлая охристая краска | `#BDA486` | тонкий фоновый защитный узор |
| бумага | `#D3C2A4` | медленно меняющийся фон, не печатный слой |

Это оценки в RGB сканера, а не колориметрические измерения пигментов. На них
влияют старение бумаги, баланс белого и профиль сканера.

Алгоритм выполняет следующие операции:

1. Восстанавливает десять марок в общей системе координат по существующим JSON.
2. Оценивает цвет бумаги отдельно для каждого экземпляра по внешнему полю.
3. Находит три направления краски в пространстве оптической плотности.
4. Разлагает каждый пиксель на неотрицательные вклады трёх красок. Это важно в
   областях наложения: жёсткая классификация «один пиксель — одна краска» там
   теряет слабую компоненту.
5. Для слабой охристой краски удаляет медленное изменение тона бумаги
   полосовым фильтром и маскирует только действительно плотные участки других
   красок.
6. Начинает регистрацию фонового узора с одной чистой резкой марки, а не с уже
   размытой медианы. Для текущего набора используется марка 5.
7. Оценивает для каждой краски независимый субпиксельный перенос и только после
   этого строит робастную медиану слоя.

Для фонового узора поиск ограничен четырьмя пикселями исходного скана. Без
ограничения периодическая сетка иногда перескакивала на соседний раппорт и
давала ложные сдвиги 6–13 px.

Полноразмерный эксперимент на десяти марках дал следующий разброс остаточных
сдвигов при 1200 dpi:

| Слой | Разброс X, px | Разброс Y, px | Медианная ECC |
| --- | ---: | ---: | ---: |
| тёмный | 2,80 | 0,30 | 0,88 |
| красный | 5,25 | 7,84 | 0,54 |
| фоновый узор | 0,75 | 2,06 | 0,20 |

Низкая ECC слабого слоя ожидаема: линии тонкие, часть узора перекрыта плотными
красками, а бумажная фактура и гашения сильнее полезного сигнала. Поэтому этот
слой пока следует считать экспериментальной реконструкцией. При этом на
контрастной карте повторяемая сетка после независимой регистрации становится
заметно плотнее, чем при обычном усреднении.

### Запуск

Из корня репозитория:

```bat
.venv\Scripts\python.exe design_components\background_pattern_refinement.py ^
  "D:\workspace\IX vs X\XIX\1R.jpg" ^
  --pattern-anchor 5 ^
  --output "D:\workspace\IX vs X\experiments\1R_background_pattern"
```

Рядом со сканом должны находиться:

- `data_1R_perf.json`;
- `data_1R_design.json`.

Основные результаты:

| Файл | Содержимое |
| --- | --- |
| `background_pattern_before_after.png` | контрастное сравнение слабого узора до и после собственной регистрации |
| `ink_1_refined.png` | тёмный слой |
| `ink_2_refined.png` | красный слой |
| `ink_3_refined.png` | слабый узор в оценённом цвете |
| `ink_3_density.png` | высококонтрастная карта слабого узора |
| `four_colour_refined.png` | композиция трёх красок на оценённой бумаге |
| `individual_pattern_inputs.png` | контроль выделения узора на каждой исходной марке |
| `per_stamp_shifts.csv` | независимые сдвиги и ECC всех слоёв |
| `result.json` | цвета, диагностические показатели и параметры результата |

Для быстрого диагностического прогона можно добавить `--downsample 2`. Финальные
значения следует получать без downsample.

## Рассмотренные варианты

### 1. Кластеризация только по микросдвигам

Файл: `two_pass_decomposition.py`.

На зарегистрированных марках строилось плотное поле оптического потока. Пиксели
кластеризовались по векторам движения без знания цвета, а цветовое разбиение
использовалось как независимый контроль.

Результат: ни одна из серий `1K–70K` не прошла консервативный критерий слепого
разделения. Совпадение motion-only и цветовой масок обычно находилось около
случайного уровня 0,5–0,6. Оптический поток смешивал приводку печати с
деформацией бумаги, ошибками общей регистрации, растискиванием и текстурой
сканера.

Полезный результат этого этапа: когда краски цветово различимы, цвет даёт
начальную маску, после которой относительный сдвиг проходов уже можно измерять.
Наиболее убедительно это работало для `14K`; для `2K` марки 1 и 12 подтвердили
различие цвета, но относительный сдвиг был меньше 0,14 px.

### 2. Две сильные краски плюс бумага для XIX/1R

Файл: `three_colour_refinement.py`.

Тёмный и красный слои разделялись в пространстве оптической плотности и
регистрировались независимо. Контуры красного герба стали значительно чётче;
сходство красного слоя с итоговым шаблоном выросло примерно на 7,3%.

Ограничение: третий слабый кластер был ошибочно принят за вариацию бумаги.
Вариант полезен как промежуточная база для двух сильных красок, но не является
полной моделью изображения.

### 3. Три краски плюс бумага, слабый слой из общей медианы

Ранний вариант текущего алгоритма принудительно искал три краски в уже
усреднённом изображении. Цвет слабого слоя определялся примерно как `#BDA486`,
но его рисунок оставался почти пустым, а регистрация возвращала ложные нулевые
сдвиги. Причина: фаза тонкой сетки была потеряна ещё до построения её маски.

Исправление: извлекать цветовой отклик на каждой отдельной марке и начинать с
резкого шаблона одной чистой марки. Эта логика реализована в
`background_pattern_refinement.py`.

### 4. Общий фон для разных номиналов 1K–7K

Файлы: `shared_background.py` и `shared_background_sparse.py` — **отвергнуты**.

Первая версия считала дополнение одной цветовой маски вторым слоем. В фон
проникали геометрически сходные части контурных клише разных номиналов; после
усреднения они превращались в размазанные пятна.

Разреженная версия использовала только уверенные seed-пиксели и оставляла
сомнительные области неизвестными. Она была корректнее методически, но всё
равно не дала улучшения: различающиеся контуры продолжали загрязнять общий фон,
а области под непрозрачной краской не имели наблюдений. Результат нельзя
использовать как восстановленную печатную форму.

Главный вывод: нельзя усреднять разные дизайны напрямую и нельзя трактовать
дополнение маски как другой печатный слой.

## Ограничения текущего прототипа

- Используется только остаточный перенос X/Y. Различия масштаба, вращения и
  локальной деформации слоя отдельно не оцениваются.
- Гашения подавляются цветом и робастной медианой, но специальной модели
  гашения пока нет.
- Под непрозрачной тёмной краской фоновый узор непосредственно не наблюдается.
  Заполнять такие области можно только модельным предположением о периодичности
  или структуре печатной формы.
- Полосовой фильтр специально сохраняет тонкие линии, но удаляет возможную
  низкочастотную составляющую охристой печати вместе с изменением тона бумаги.
- Выбор опорной марки пока задаётся вручную. Автоматическая оценка иногда
  предпочитает погашенный экземпляр из-за более сильного контраста.
- Числа качества получены на одной коллекции из десяти марок и требуют
  проверки на независимом наборе.

## Следующие улучшения

1. Совместная генеративная модель: три общих шаблона краски, отдельное гладкое
   поле бумаги и три трансформации на каждую марку.
2. Робастная функция потерь и явная маска гашения вместо надежды только на
   медиану.
3. Автоматический выбор чистой опорной марки по доле чужой плотной краски и
   согласованию с несколькими соседями.
4. Модель периодичности фоновой сетки для восстановления закрытых участков с
   отдельной картой «наблюдалось / достроено моделью».
5. Карты покрытия и неопределённости для каждого слоя.
6. Проверка на синтетических известных сдвигах и hold-out: строить шаблон без
   одной марки и измерять, насколько он объясняет исключённый экземпляр.
7. При необходимости — отдельный малый affine для каждого слоя, но только
   после устойчивой translation-only базы.
8. Калибровочная мишень или профиль сканера для перехода от scanner RGB к
   воспроизводимым оценкам цвета.

## Статус

Все файлы каталога остаются исследовательскими. Они не импортируются
production-кодом, не вызываются существующими `.bat` и не меняют формат
текущих JSON-результатов.
